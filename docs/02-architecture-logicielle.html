Comment le systeme est construit

Le client, le backend et les trois services externes qu'il orchestre, du chargement de la page jusqu'a l'affichage du podium.

Vue d'ensemble

Le front ne parle jamais directement a Steam, Mistral ou SteamGridDB : tout passe par le backend, qui centralise les appels et met en cache ce qui peut l'etre.

Backend Identifiant utilisateur Cache Services externes

Composants

Client (Vue 3)

Interface utilisateur : ecran de connexion Steam, formulaire de criteres, affichage des 3 resultats en format podium.

Backend (TypeScript)

Orchestre l'ensemble des appels externes et applique la logique metier (cas de bibliotheque vide, cache, etc.). Hebergement prevu sur Vercel dans un premier temps.

Identifiant utilisateur interne

Des la V1, chaque utilisateur connecte se voit associer un identifiant interne (user_id), meme sans systeme de compte visible. Le SteamID64 obtenu via Steam OpenID est rattache a cet identifiant via une structure de type « liaisons de plateforme » (user_id, platform, platform_id). La session pointe vers cet identifiant interne, pas vers le SteamID64 brut — ce qui permet d'ajouter un vrai systeme de compte ou une deuxieme plateforme plus tard sans migrer la structure existante.

Cache bibliotheque Steam

Conserve temporairement les donnees de bibliotheque (jeux, temps joue, derniere session) pour eviter de solliciter la Steam Web API a chaque chargement de page. Duree de mise en cache encore a definir.

Services externes

Auth + donnees

Steam

OpenID pour la connexion (via passport-steam), puis Web API pour la bibliotheque, le temps joue et la derniere session.

IA

Mistral API

Recoit titre / genre / temps joue / derniere session par jeu, plus les criteres utilisateur. Renvoie nom + ID Steam pour 3 jeux.

Visuel

SteamGridDB

Fournit l'affiche portrait de chaque jeu a partir de son ID Steam, pour l'affichage sur les cartes du podium.

Sequence d'une requete de suggestion

  1. Chargement de la pageLe backend verifie l'identifiant utilisateur interne et le SteamID64 associe.
  2. ResynchronisationLa bibliotheque Steam est resynchronisee automatiquement (cache si valide, sinon appel a la Steam Web API).
  3. Bibliotheque vide ?Si oui, bascule sur une liste de jeux gratuits Steam.
  4. Saisie des criteresL'utilisateur renseigne humeur, fatigue, temps disponible, moment de la journee.
  5. Appel a MistralEnvoi de la liste des jeux candidats et des criteres utilisateur.
  6. Retour de l'IAMistral renvoie 3 jeux (nom + ID Steam).
  7. Recuperation des affichesLe backend interroge SteamGridDB pour chaque ID Steam.
  8. AffichageLes 3 jeux et leurs affiches sont renvoyes au client pour l'affichage en podium.
